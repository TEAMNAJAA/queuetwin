HOW IT WORKS · THE CODE

One simulation drives every number.

1
Simulatestep() advances the hospital 15 simulated seconds: patients arrive on a time-of-day curve, wait, and get served.
2
Prioritisewaiting() sorts each line: emergency → urgent → normal, then first come, first served.
3
ComparesimDayCurve() replays the whole day, 07:30–17:00, for “do nothing” and for the plan, on 3 random seeds.
4
OptimiseoptimizeSameBudget() searches staff placements per shift window with the same head-count and keeps what the simulation says is best.
5
PredictA gradient-boosting model, trained on 254,081 simulated visits, predicts each patient's wait at arrival.

    .sort((a, b) => a.urg - b.urg || a.enter - b.enter);
}

HOW WE KEEP THE NUMBERS HONEST

  • Charts, advisor and “hours saved” come from the full-day simulation, not from fixed formulas.
  • Baseline and plan run on the same random seeds and the same starting staff.
  • Every saving is shown next to its cost in staff-hours.
  • Sponsor actions say LIVE only when the API confirms; otherwise they are labelled Sandbox.
  • Public QR and cloud data mask the surname and hide clinical details.
Patients, arrival curve and service times are simulated assumptions. A real pilot would calibrate them from a clinic's own queue log.
